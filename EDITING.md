# Editing the OpenWDL Website

All content lives under `site/src/content/`. Content is validated at build
time, so a malformed front matter block fails the build rather than shipping a
broken page. Run `npm run dev -w @openwdl/site` from the repository root to
preview changes.

## Adding a blog post

Create `site/src/content/blog/<slug>.md`:

```markdown
---
slug: announcing-wdl-1-3-0
title: "Announcing WDL 1.3.0"
date: 2026-01-10T12:00:00-06:00
authors: [clay-mcleod]
genre: release
standfirst: "One or two sentences shown in listings and social previews."
featured: true
version: 1.3.0
specUrl: "https://github.com/openwdl/wdl/blob/wdl-1.3/SPEC.md"
legacyPath: "/wdl/bioinformatics/workflows/announcing-wdl-1-3-0/"
---

Post body in Markdown.
```

| Field         | Required | Notes                                                              |
| ------------- | -------- | ------------------------------------------------------------------ |
| `slug`        | yes      | Lowercase and hyphen-separated; becomes `/blog/<slug>/`.            |
| `title`       | yes      | Non-empty.                                                          |
| `date`        | yes      | ISO 8601 timestamp.                                                 |
| `authors`     | yes      | One or more ids from `site/src/content/authorIds.ts`.               |
| `genre`       | yes      | `release`, `report`, `tool`, `guide`, or `meta`.                    |
| `standfirst`  | yes      | Summary used in listings and metadata.                              |
| `featured`    | no       | Promotes the post on the blog index.                                |
| `version`     | no       | WDL version the post announces.                                     |
| `specUrl`     | no       | Link to the relevant specification.                                 |
| `legacyPath`  | no       | Old Jekyll URL; prerendered as a redirect to the new one.           |

Images go in `site/public/blog-assets/` and are referenced with a rooted path,
for example `![Diagram](/blog-assets/diagram.png)`.

### Adding an author

Add the id to `AUTHOR_IDS` in `site/src/content/authorIds.ts`, add the entry to
`authors` in `site/src/content/authors.ts`, and drop the avatar into
`site/src/assets/authors/`.

## Adding a documentation page

Create a Markdown file under `site/src/content/docs/<section>/`:

```markdown
---
title: "Tasks"
description: "Atomic units of computation with command, input, output, and requirements sections."
slug: /docs/start/language/tasks/
section: learn
group: "Language guide"
order: 40
kind: guide
legacy:
  - /docs/write/tasks/
  - /language-guide/tasks
---

Page body in Markdown.
```

| Field             | Required | Notes                                                        |
| ----------------- | -------- | ------------------------------------------------------------ |
| `title`           | yes      | Page heading and nav label.                                   |
| `description`     | yes      | Used for metadata and search.                                 |
| `slug`            | yes      | Must match `/docs/.../` with a trailing slash.                |
| `section`         | yes      | `learn`, `production`, `stdlib`, or `upgrading`.                    |
| `group`           | yes      | Sidebar grouping label.                                       |
| `order`           | yes      | Non-negative integer controlling order within the group.      |
| `kind`            | yes      | `tutorial`, `guide`, `pattern`, or `reference`.               |
| `legacy`          | yes      | Old URLs to redirect from; use `[]` for new pages.            |
| `minutes`         | no       | Estimated reading time.                                       |
| `headingAliases`  | no       | Maps old anchor ids to current headings.                      |
| `hidden`          | no       | Excludes the page from navigation.                            |

Unknown front matter keys are rejected. Docs are compiled into
`site/src/generated/` and a client-side search index under
`site/public/search/`, both regenerated by `npm run build:content -w
@openwdl/site` (which `dev` and `build` run for you). The search index has a
500 KB gzipped budget that the build enforces.

Platform-specific command samples use synchronized tabs. Mark only those tab groups
with `sync="platform"`; ordinary comparison tabs remain independent:

```markdown
::::tabs{sync="platform"}
:::tab{label="macOS"}
macOS command
:::
:::tab{label="Linux"}
Linux command
:::
:::tab{label="Windows"}
Windows command
:::
::::
```

The labels must be exactly `macOS`, `Linux`, and `Windows`. A reader's selection is
stored locally and applied to other synchronized groups.

Use `:kbd[Key]` for keyboard keys, such as
`Press :kbd[⌘] + :kbd[Space]`.

Use `:badge[Label]` for a short inline badge, such as
`## Build from source :badge[Bonus]`.

Every Production guide section after **Git crash course** must begin with
`## Start this section`. Use this template:

````markdown
## Start this section

From the course directory, update the `main` branch in your fork:

```bash
git switch main
# Already on 'main'
# or: Switched to branch 'main'
git pull --ff-only fork main
# Already up to date.
git status --short
# No output is expected.
```

`git pull --ff-only` downloads progress from the fork without creating a merge commit.
The empty output from `git status --short` means you have a clean starting copy.
````

Follow that block with `## Introduction` before the lesson's other headings.

Before the final summary, add `## Save your progress` with explicit `git add` paths, a
focused commit message, and `git push fork main`. End with `## What you learned`.

## Redirects and routes

Site routes, including redirects from legacy Jekyll URLs, are declared in
`site/src/routes/manifest.ts` and prerendered as static redirect pages.

## Before opening a pull request

```sh
npm run lint -w @openwdl/site
npm test -w @openwdl/site
npm run build -w @openwdl/site
```
